# paintSMYS — Product Requirements Document

**Статус:** продуктовые требования и целевой план; фактическую готовность функций нужно подтвердить аудитом репозитория.  
**Платформы:** desktop-приложение на Electron в первой версии; Browser Editor и Web Viewer — будущие приложения на общей логике и UI.  
**Связанный документ:** [ARCHITECTURE.md](./ARCHITECTURE.md).

## 1. Видение продукта

paintSMYS — локальный объектный графический редактор с визуальной эстетикой Microsoft Paint / Windows 95 и современными возможностями редактирования.

Пользователь создаёт графику из отдельных объектов, редактирует их свойства и сохраняет проект вместе с его ресурсами в переносимую папку. Продукт должен быть полезен для создания графики к YouTube и другим медиа, технических схем и иллюстраций.

Внешний вид намеренно напоминает старый Paint. Работа с данными, сохранением и редактированием должна быть надёжной и понятной.

## 2. Для кого и для каких задач

Основные задачи пользователя:

- создавать графику для видео и других медиа;
- рисовать технические схемы и иллюстрации;
- размещать и точно редактировать объекты, текст, изображения и в дальнейшем кодовые блоки;
- задавать свойства объектов через Inspector;
- сохранять проект со всеми нужными ресурсами и переносить его между директориями;
- экспортировать результат для использования вне приложения.

В будущем пользователь должен иметь возможность запускать общий редактор в браузере и встраивать опубликованную сцену в цифровой сад через Web Viewer. Web Viewer показывает сцену и ресурсы проекта без инструментов редактирования и Electron. Редактор также должен допускать автоматизацию через документированный API и плагины. Эти направления не блокируют выпуск Desktop-продукта.

## 3. Продуктовые принципы

1. **Local-first:** пользователь работает с локальными файлами; облачные аккаунты и синхронизация не нужны для первой версии.
2. **Проект переносим:** проект — папка с манифестом и ресурсами, а не запись в скрытой базе приложения.
3. **Редактирование объектное:** размеры и свойства объектов доступны для точного изменения.
4. **Данные защищены:** ошибки сохранения и отмена диалогов не должны незаметно терять активный документ.
5. **Разработка идёт сценариями:** сначала создание, открытие, редактирование и сохранение, затем ресурсы, экспорт и расширения.
6. **Сохраняем работающий код:** существующие Rectangle Tool, Select, Drag, Delete и Property Inspector сначала проверяются; работающее поведение не переписывается ради структуры каталогов.
7. **Desktop и Web используют общий Editor UI и Document Core:** различия платформы подключаются через отдельные узкие адаптеры.

## 4. Границы первой версии

### Входит в целевой первый законченный продукт

- стартовый экран с созданием и открытием проекта;
- создание сцены с готовым или пользовательским размером Artboard;
- редактирование объектов на Artboard;
- Inspector для свойств сцены и выбранного объекта;
- сохранение проекта в выбранную директорию и повторное открытие;
- защита от потери несохранённых изменений;
- импорт изображений внутрь проекта;
- экспорт сцены в PNG.

Функции вводятся по этапам, описанным в разделе «План реализации». Полный перечень целевого первого продукта не означает, что всё нужно реализовать одним изменением.

### Не входит в первую версию

- облачные аккаунты и синхронизация;
- Browser Editor и Web Viewer как пользовательские приложения;
- marketplace плагинов и менеджер плагинов;
- публичный Plugin SDK, MCP-сервер и автоматизация через AI API;
- собственный менеджер файлов и база проектов;
- несколько сцен и несколько Artboards;
- универсальная система инструментов, глобальный Command Bus и Event Bus.

## 5. Пользовательские сценарии и требования

### 5.1 Запуск и создание проекта

При запуске пользователь видит компактный экран Welcome в стиле Windows 95 с действиями **New Project** и **Open Project**. Экран не должен превращаться в полноэкранный каталог шаблонов.

При выборе New Project пользователь сразу видит плитки размеров:

| Пресет | Размер |
| --- | ---: |
| Full HD | 1920 × 1080 |
| HD | 1280 × 720 |
| 4K | 3840 × 2160 |
| Vertical | 1080 × 1920 |
| Square | 1080 × 1080 |
| Custom | Ручной ввод |

Выбор готового пресета сразу создаёт проект и открывает редактор. Custom показывает компактный диалог Width / Height / Create. Artboard нового проекта имеет белый фон. При создании папку на диске выбирать не требуется.

### 5.2 Редактирование в редакторе

Экран редактора содержит панель инструментов, рабочую область, Artboard, объекты сцены, Inspector справа и меню File / Edit / View. Статус проекта показывает имя или состояние сохранения, когда оно доступно.

Пользователь может создавать и редактировать объекты доступными инструментами. Реализованные Rectangle Tool, выделение, Drag, Delete и Inspector сохраняются после проверки их текущего поведения.

### 5.3 Inspector и свойства

Inspector закреплён справа и открыт по умолчанию на широких окнах. Его видимость не меняется автоматически при выборе объекта.

Когда объект не выбран, Inspector показывает Scene Properties:

- Artboard Width и Height;
- Background Color или Transparent;
- Scene ID в режиме только чтения.

При выбранном объекте пользователь может переключиться на Scene Properties через вкладку Scene.

Для Rectangle Inspector показывает:

- X и Y;
- Width и Height;
- вычисляемые X2 и Y2;
- Fill, Stroke и Stroke Width;
- Object ID и Type.

Изменение размера Artboard не сдвигает и не масштабирует объекты. Объекты за границами Artboard остаются в сцене. X2/Y2 вычисляются из положения и размера, а не редактируются как независимые координаты.

Меню View → Properties переключает Inspector. Выбор пользователя сохраняется между запусками. Изменение размера окна меняет компоновку, но не предпочтение видимости. На узких окнах допустим режим панели поверх редактора.

### 5.4 Открытие проекта

Пользователь выбирает папку проекта через системный файловый диалог. Приложение проверяет наличие `project.json`, читает и валидирует манифест, версию формата и ссылки на ресурсы, затем открывает сцену.

Если проект повреждён или несовместим, приложение показывает ошибку. Текущая открытая сессия сохраняется. Отмена выбора папки также не меняет текущий проект.

### 5.5 Сохранение проекта

До первого сохранения проект является несохранённой сессией. При первом Save пользователь выбирает родительскую папку и имя проекта; приложение создаёт внутри неё директорию проекта.

Повторный Save записывает изменения в текущую папку проекта. Save As создаёт независимую копию проекта и необходимых ресурсов в новой директории. Приложение не должно молча перезаписывать чужой проект.

При закрытии или замене проекта с несохранёнными изменениями предлагаются **Save / Don’t Save / Cancel**. Отмена сохранения, ошибка диска или отмена диалога не должны приводить к потере активного документа.

### 5.6 Импорт изображений

При импорте изображения приложение проверяет поддерживаемый формат, копирует исходный файл в `assets/` проекта и создаёт объект сцены со ссылкой на скопированный ресурс. После импорта сцена не зависит от файла в Downloads, Desktop или другой исходной папке.

Для несохранённого проекта временное хранилище ресурсов создаётся вместе с реализацией импорта. При первом Save ресурсы перемещаются или копируются в директорию проекта.

### 5.7 Экспорт

Пользователь может экспортировать сцену в PNG в точных размерах Artboard. Экспорт поддерживает прозрачность, если для сцены выбран прозрачный фон.

## 6. Требования к проектным данным

Проект хранится как переносимая директория:

```text
my-project/
├── project.json
└── assets/
    ├── image-001.png
    └── logo.svg
```

Манифест содержит метаданные проекта и сериализованную сцену. Для первого этапа достаточно одной сцены. Версии формата проекта и схемы сцены задаются явно.

Пути к пользовательским ресурсам должны быть переносимыми. Абсолютные пути исходных файлов не записываются. Загрузка проекта запрещает небезопасные относительные пути, выходящие за пределы папки проекта. Ошибка сохранения не должна повреждать ранее сохранённый манифест.

Фактическая структура сериализации согласуется с существующими типами `SceneDocument` и проверками Core; концептуальный формат описан в [ARCHITECTURE.md](./ARCHITECTURE.md).

## 7. Визуальное направление

Интерфейс следует эстетике Microsoft Paint / Windows 95:

- серый фон;
- рельефные рамки;
- утопленные поля;
- компактные контролы;
- закреплённый справа Inspector.

Стилизация не должна мешать точному редактированию, ясному отображению ошибок и защите пользовательских данных.

## 8. План поставки

### Этап 0 — Audit

Проверить Document Core, Rectangle Drawing, Select / Drag / Delete, Inspector, Artboard, тесты и Git status. Отметить реализованное и запланированное. Не переписывать работающий код ради соответствия целевой схеме папок.

### Этап 1 — New Project

Реализовать Welcome → New → Preset / Custom → Editor.

**Критерий:** готовый размер создаёт рабочую сцену одним выбором; Custom создаёт сцену с введёнными размерами.

### Этап 2 — Project Folder Storage

Добавить манифест, состояние Project Session, нативный Open, Save / Save As, валидацию и безопасную запись.

**Критерий:** пользователь создаёт проект, рисует, сохраняет, закрывает, открывает снова и видит прежний Artboard и объекты.

### Этап 3 — Data Safety

Добавить dirty state, Save / Don’t Save / Cancel для New / Open / Close, защиту сессии при ошибках и корректную обработку отмены.

**Критерий:** случайное закрытие или ошибка сохранения не приводят к незаметной потере изменений.

### Этап 4 — Asset Import

Добавить Image Object, копирование изображений в `assets/`, переносимые ссылки и временное хранилище несохранённой сессии.

**Критерий:** после переноса папки проекта изображения продолжают открываться.

### Этап 5 — Export

Добавить экспорт PNG с размером Artboard и поддержкой прозрачности.

**Критерий:** пользователь получает PNG требуемого разрешения.

### Этап 6 — Editor Productivity

Добавить или завершить Undo/Redo, текст, Code Block, Windows 95 Window Object и базовое управление композицией.

**Критерий:** редактор позволяет собрать полезную техническую иллюстрацию для видео.

### Этап 7 — Plugin Readiness

После появления законченного редактора определить минимальный API, подготовить тестовый host и conformance-тесты, проверить стороннее расширение по документации.

**Критерий:** агент может создать и изменить объект через документированный API и прочитать состояние, чтобы проверить результат.

### Будущие web-сценарии

**Web Viewer:** отдельный облегчённый экран для опубликованного `project.json` и ресурсов из `assets/`, который можно встроить в цифровой сад. Он не содержит инструментов редактирования и не использует Electron.

**Browser Editor:** общий React Editor запускается в браузере через отдельный entrypoint. Проектные сценарии используют web-адаптер, учитывающий ограничения браузерного доступа к файлам и выбранный способ хранения.

Обе возможности находятся за пределами первой Desktop-версии. Их общие Core и Editor UI не должны дублироваться.

## 9. Критерии готовности первого законченного продукта

Пользователь может:

1. Запустить paintSMYS.
2. Создать проект или открыть папку существующего проекта.
3. Работать с объектами на Artboard.
4. Редактировать свойства сцены и объектов.
5. Сохранить проект в выбранной директории.
6. Закрыть приложение и снова открыть проект без потери данных.
7. Импортировать изображения, которые хранятся внутри проекта.
8. Экспортировать PNG для использования вне paintSMYS.

Цель — редактор, пригодный для реальной работы, а не только для демонстрации интерфейса.

## 10. Проверки релизных срезов

После каждого законченного сценария планируются TypeScript typecheck, ESLint, unit-тесты, интеграционные тесты Project Storage, Electron E2E сценария, build и проверка Git diff.

Для сохранения и открытия особенно важны сценарии New → Save → Open, отмена диалога, повреждённый `project.json`, несовместимая версия, ошибка записи, dirty state и сохранение Artboard с объектами. Логику Core и Application следует проверять без React.
