## Цель

Довести paintSMYS до сценария, в котором человек может попросить AI-агента создать плагин, установить его в приложение и получить новую функцию без изменения исходников paintSMYS.

Первое доказательство — **Win95 Code Card**: пользователь вводит код, выбирает язык и заголовок окна, получает на Artboard редактируемую композицию в виде окна Windows 95, сохраняет проект и экспортирует PNG.

Это должен быть внешний плагин с собственными манифестом и кодом. Его результат состоит из стандартных объектов paintSMYS и остаётся доступен для редактирования, сохранения и экспорта даже после удаления плагина.

## Критерий первой большой финишной черты

Человек, не менявший исходники paintSMYS, может:

1. взять пример плагина и попросить AI-агента изменить его или создать аналог;
2. установить плагин из локальной папки;
3. запустить Win95 Code Card и добавить результат в документ;
4. отменить добавление одной командой Undo, повторить его Redo, сохранить проект и экспортировать PNG;
5. удалить плагин, не потеряв созданную композицию.

Установка из Git, публикация примеров и проверка совместимости плагинов развивают этот сценарий, но не должны задерживать первую локальную демонстрацию.

## Этапы

### 00 — База редактора

**Статус: готово.** Есть создание и открытие проекта, сохранение, Rectangle, Select/Delete и Undo/Redo. Перед дальнейшей работой сохраняем существующие сценарии и не переписываем работающий код ради расширяемости.

### 01 — Перемещение прямоугольника

**Статус: в работе.** Перетаскивание объекта инструментом Select и запись перемещения одним действием Undo реализованы в текущих незакоммиченных изменениях. Критерий ещё не подтверждён отдельной проверкой.

**Готово, когда:** прямоугольник можно перемещать мышью, после завершения жеста Undo возвращает его в исходное положение одним шагом, а Redo восстанавливает новое.

### 02 — Текстовый объект

**Статус: не начато.**

Добавить стандартный объект Text: текст в несколько строк, шрифт, размер и цвет. Объект можно разместить, выделить, удалить и редактировать доступными простыми контролами. Полноценный текстовый редактор и сложная типографика пока не нужны.

**Готово, когда:** текст отображается на Artboard и проходит полный цикл редактирования, Undo/Redo, Save и Open.

### 03 — Экспорт PNG

**Статус: не начато.**

Экспортировать весь Artboard в PNG в его точном разрешении; поддержать прозрачный фон, если он выбран в документе.

**Готово, когда:** сохранённый PNG имеет ожидаемый размер и визуально совпадает с композицией на Artboard.

### 04 — Прототип Win95 Code Card

**Статус: не начато.**

Проверить пользовательский результат до проектирования общего плагинного API: ввод кода, выбор языка и заголовка, создание окна Notepad в стиле Windows 95 с подсветкой синтаксиса.

Прототип создаёт обычные Rectangle и Text. Не вводить специальный тип объекта Code Card: результат должен редактироваться существующими средствами и быть понятен документу без кода плагина.

**Готово, когда:** композицию можно настроить, добавить на Artboard, сохранить и экспортировать без потери текста и оформления.

### 05 — Plugin API v0 и внешний Code Card

**Статус: не начато.**

Добавить минимальный API для **action-плагинов**: плагин принимает входные данные и возвращает набор поддерживаемых операций или объектов; host проверяет результат и применяет его к документу как одно пользовательское действие.

Первый API не требует плагинных инструментов с обработкой указателя. Плагин создаёт стандартные объекты через публичный контракт и не меняет внутреннее состояние документа напрямую.

Пример внешнего репозитория:

```text
paintsmys-win95-codecard/
├── manifest.json
├── index.js
├── README.md
└── preview.png
```

**Требования к host:**

- проверять манифест, версию API, входные данные и каждую операцию;
- ограничивать возможности плагина документированным API;
- не запускать сторонний JavaScript в привилегированном Electron-контексте;
- определить изоляцию выполнения и явную модель разрешений до запуска стороннего кода;
- применять всю композицию одной записью истории Undo;
- сохранять в проекте обычные поддерживаемые объекты, не требующие установленного плагина.

**Готово, когда:** Code Card вынесен из приложения в отдельный репозиторий, устанавливается как внешний плагин и проходит весь сценарий первой финишной черты.

### 06 — Установка и авторство плагинов с AI

**Статус: не начато.**

Развивать путь **Clone → Modify → Share**:

1. установка из локальной папки;
2. клонирование официального примера и проверка структуры/манифеста;
3. установка из Git-репозитория;
4. инструкция для AI-агентов: API, доступные операции, ограничения, пример и способ проверить результат.

Подготовить официальный Plugin Authoring Skill для AI-агентов, когда формат API и инструкции стабилизируются. Встраивать собственный AI-чат в редактор для этого не требуется.

**Готово, когда:** агент может создать или изменить совместимый плагин по примеру и документации, а пользователь может проверить и установить его без правок исходников приложения.

### 07 — Первое сообщество

**Статус: не начато.**

Собирать внешние примеры и пользовательские плагины, документировать совместимость и делиться результатами. Начать с репозиториев и каталога проверенных ссылок; полноценный marketplace не входит в эту финишную черту.

**Готово, когда:** автор, кроме разработчика paintSMYS, создал и поделился плагином, который другой пользователь установил и запустил.

## Пока не блокирует эту цель

Resize Handles, полноценный Inspector, Ellipse, Line, кисть, слои и группировка не входят в путь к первому плагину, если конкретная функция не потребуется для его сценария. Полная картина целевого продукта описана в [PRD](./PRD.md).

Также за этой финишной чертой остаются marketplace, универсальные Tool Plugins, экспортные плагины, Browser Editor и Web Viewer. Их можно планировать отдельно после проверки интереса к внешнему API.

## Решения, которые нужно принять по мере приближения

- выбрать техническую границу изоляции плагинного кода и формат подтверждения разрешений;
- зафиксировать версионирование манифеста и Plugin API v0;
- определить допустимые размеры/сложность результата, чтобы host мог безопасно валидировать операцию.

Это задачи этапа Plugin API, а не причины откладывать Text, PNG или проверку самого Code Card.
